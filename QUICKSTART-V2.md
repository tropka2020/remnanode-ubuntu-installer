# NORTH / STILL / RITUAL — короткая установка Ubuntu 24.04

## Что изменилось

Новая версия использует три фотодизайна и автономный выбор параметров без вопроса о реестре:

1. **NORTH** — природа и путешествия.
2. **STILL** — интерьер, свет и материалы.
3. **RITUAL** — кофе и домашние рецепты.

Название автоматически выбирается из семейства шаблона; seed задаёт совместимое оформление, порядок материалов и кадрирование. В каждой семье есть главная, список материалов, о проекте и пять отдельных полноценных HTML-статей. Анимация локальная и необязательная, ссылки и mobile-menu работают без JavaScript. Это разнообразие конечного набора, не гарантия отсутствия повторов между серверами и не гарантия нераспознаваемости VPN/генератора.

## Подготовка

Новый Ubuntu 24.04 amd64/arm64, systemd, root, Python3, SSH и консоль провайдера. Сделайте snapshot. До любых вопросов мастер проверяет **полный размер файловой системы `/`**, а не свободное место. При размере **не менее 6 ГиБ** расширение не выполняется. Если размер меньше 6 ГиБ, автоматическое расширение возможно только для ext4 непосредственно на разделе: родительский диск должен быть уже увеличен у провайдера, а доступный конец раздела должен позволять получить **не менее 15 ГиБ**. Раздел и ext4 увеличиваются до всего доступного конца, не ровно до 15 ГиБ; если раздел уже увеличен, расширяется только ext4. `growpart` и `resize2fs` должны быть уже установлены: мастер не устанавливает инструменты через APT для обхода этой проверки. Неизвестная/неподдерживаемая схема, недостаточный размер или отсутствие инструментов останавливают установку до пакетов, без удаления или пересоздания разделов.

Автоматическое перемещение устаревшего резервного GPT-заголовка (stale GPT после увеличения диска) не поддерживается: при недостаточных usable LBA мастер остановится с рекомендацией ручной диагностики, не ослабляя проверку границ. Для диска ровно15ГиБ раздел обычно будет меньше15ГиБ из-за служебных областей; ориентир — достаточный доступный размер самого раздела.

Проверка и сводка до подтверждения ничего не меняют. План с устройствами и размерами показывается перед единственным подтверждением `УСТАНОВИТЬ`. Само расширение выполняется под блокировкой, после повторной проверки сервера и успешного резервирования дизайна, до APT/Docker. Оно требует snapshot и **не откатывается уменьшением раздела или ext4**, даже если последующая установка завершится ошибкой.

Рекомендуется запас **2 ГиБ свободного места** и 10000 свободных inode на файловых системах загрузки/развёртывания. Проверка нехватки свободного места только предупреждает и не блокирует установку; это отдельная проверка, не порог полного размера `/`. Диск всё ещё может заполниться при APT/Docker; продолжение не гарантирует успех. Автоматической очистки нет. Размер диска выбирайте с запасом под обновления ОС, Docker и логи.

Домен: A-запись напрямую на сервер, без CDN/proxy; текущий IPv4 inbound не принимает AAAA в мастере. Firewall провайдера должен разрешать ваш SSH, TCP80/443, API2222 только панели. Секрет ноды берётся из окна добавления ноды в панели, не придумывается установщиком.

Перенесите полный архив, а не отдельный installer.py. Исходники и предки должны принадлежать root и не допускать запись другим. Рекомендуемый путь `/opt/remnanode-local`. Не запускайте поверх действующей установки.

```bash
cd /opt/remnanode-local
sha256sum -c SHA256SUMS
bash install-remnanode.sh
```

## Только нужные вопросы

1. Домен.
2. IPv4 панели.
3. SECRET_KEY (ввод скрыт).
4. Шаблон1/2/3.
5. Одно подтверждение общей сводки.
6. После применения UFW — **проверить новое SSH-подключение** и подтвердить, что оно работает. Это обязательная защита, а не лишний вопрос.

АВТОНОМНО выбирается автоматически, URL/токен реестра и название не запрашиваются. Старые legacy registry state/manifests сохраняются без автоматического сброса. Новый manifest лежит вне сайта:

```text
/var/lib/remnanode-design/premium-manifest.json
```

Повтор после ошибки с тем же шаблоном использует прежний seed. Для смены шаблона на установленном сервере — меню selfsteal, не перезапуск мастера.

## Что установится и как отображается процесс

Перед стартом виден список предстоящих этапов, при переходе этапа — обновлённые статусы. Галочка ставится после успешного выполнения соответствующего этапа, текущий этап отмечается стрелкой; для долгой команды каждые10с печатается ожидание с длительностью. Формат обычного текста работает и в non-TTY, без очистки экрана/ANSI-перерисовки.

```text
[✓] Проверка сервера
[✓] Диск
[✓] Настройки
[✓] Дизайн
[→] APT/Docker
[ ] Образы
[ ] Сайт/Caddy
[ ] Нода
[ ] Logrotate
[ ] UFW/SSH
[ ] Fail2ban
[ ] BBR
[ ] Selfsteal
[ ] Итог
```

Этап «Диск» сначала показывает только проверку без изменений и остаётся без галочки до подтверждения, резервирования дизайна и успешного применения плана. При `/` не менее 6 ГиБ он сообщает «без изменений». Детали расширения выводятся отдельно; успешная проверка сама по себе не означает выполненное расширение.

Подробные вложенные этапы показываются отдельно. Сырые stdout/stderr команд с ключами/секретами не печатаются; это не процент загрузки Docker. Если BBR/Fail2ban пропущены по безопасной причине, отдельная строка сообщает «пропущено» и почему; завершённая проверка не означает, что неподдерживаемая функция была включена.

- Docker/Compose — официальный подписанный APT-источник; рабочий Docker сохраняется, чужие конфликтующие пакеты не удаляются.
- Node — YAML `remnawave/node:latest`, `restart: always`, host network, NET_ADMIN, nofile1048576, `/var/log/remnanode:/var/log/remnanode`.
- Caddy — pinned digest, HTTP80 ACME HTTP-01, локальный HTTPS127.0.0.1:9443, постоянные certificate volumes; access.log вне сайта.
- Logrotate Xray —50M,5архивов,compress,missingok,notifempty,copytruncate; штатный timer.
- UFW — безопасная SSH-проверка/таймер отката, публичные80/443, API2222 только панели, backend9443 не открывается наружу.
- Fail2ban — только SSH jail, обнаруженные порты, journald backend, nftables action, проверка до включения. Текущий SSH-клиент исключён точным IP и записан в jail. Не меняет sshd_config. Уже установленная/чужая конфигурация не перезаписывается, вместо этого сообщается skip. Автозапуск во время APT подавляется до проверки jail; пакеты при откате остаются.
- BBR — проверяет ядро, qdisc и старые настройки; загружает штатный модуль и меняет только TCP congestion control, если безопасно. Существующий fq/fq_codel сохраняется. При конфликте/неподдерживаемом окружении — skip с причиной, не kernel download.

## Производительность: что это НЕ делает

Никаких автоматических MTU/offload/TCP-buffer/backlog/conntrack/CPU-governor изменений, отключения UFW, установки сторонних ядер, swap или benchmark к чужим серверам. BBR влияет на новые TCP-соединения, не ускоряет UDP напрямую и не снимает ограничения тарифа/CPU/маршрута. «Настройка включена» не равно «скорость измерена».

Перед оценкой скорости уточните тариф и проверьте приём/отдачу с контролируемого endpoint напрямую и через VPN. Во время теста смотрите CPU/steal/loss/очереди. Установка не обещает максимальную скорость и не создаёт искусственный результат speedtest.

## Профиль — в панели Remnawave

Установщик сохраняет только пример `config-profile.json`, host-параметры и памятку; конфигурация применяется панелью. Создайте профиль в панели, назначьте ноде и нужному Internal Squad. Серверный inbound443: VLESS/REALITY, target127.0.0.1:9443, xver0, SNI вашего домена. Секрет API не равен private key REALITY. Private key не отправляйте клиентам или в GitHub.

До применения профиля публичный443 не объявляется работающим. Сам мастер проверяет backend сертификат и HTTP локально. Внешнюю доступность/пользовательскую авторизацию проверяйте отдельно.

## Selfsteal и смена шаблона

Менеджер копируется в `/usr/local/lib/remnanode-manager`, wrapper — `/usr/local/bin/selfsteal`. После этого не зависит от исходного download-каталога. Чужая команда selfsteal не перезаписывается; конфликт обнаруживается до установки. Точный runtime содержит только allowlist модулей/ресурсов, не секреты и не ZIP.

```bash
selfsteal
selfsteal status
selfsteal logs --kind visits --lines 100
selfsteal logs --kind errors --lines 100
selfsteal template --template 1 --confirm
selfsteal template --template 2 --confirm
selfsteal template --template 3 --confirm
```

В меню пункт8 — «Сменить шаблон сайта». Сначала подготовка и exact-byte проверка нового сайта, затем одна явная просьба подтвердить перерыв. CLI `--confirm` заменяет интерактивное подтверждение.

Меняется только HTML/assets и приватный manifest. Делается private backup. Caddy кратковременно останавливается для переподключения bind mount, новый HTTPS ожидается с retry. При ошибке сайт и manifest восстанавливаются. Если остановка не подтверждена, потенциально живые деревья не удаляются и требуется ручная проверка.

Node, профиль, ключи, UFW, сертификаты и Docker volumes при смене не меняются. Stop/start/restart также относятся только к Caddy. Сертификаты продлевает Caddy автоматически; renew-check не удаляет сертификаты ради принудительного выпуска.

Для старого комплекта установка менеджера — отдельное явное действие, не мастер новой установки:

```bash
python3 selfsteal.py install-command
```

Новая команда не притворяется старым сторонним DigneZzZ selfsteal.sh. Не заменяйте чужой runtime вручную. Импорт произвольных пользовательских сайтов по-прежнему запрещает JS; только наш premium renderer публикуется через exact expected-files проверку.

## Чистый повтор после неудачной попытки

Если мастер завершился ошибкой и контейнеров уже нет, сначала запускайте только read-only проверку:

```bash
python3 prepare_fresh_install.py
```

Она проверяет контейнеры, активные UFW rollback timers, Fail2ban, dpkg и известные каталоги. По умолчанию ничего не перемещает и не удаляет. Для архивации только проверенных путей после явного подтверждения:

```bash
python3 prepare_fresh_install.py --apply
```

Скрипт перемещает `/opt/remnanode`, `/opt/caddy`, `/opt/remnanode-local`, private design state и распознанный runtime в закрытую папку `/var/backups/remnanode-local/fresh-start-*`. Он не удаляет Docker volumes, образы, пакеты, логи, UFW или чужие каталоги. Если есть контейнеры, активный rollback timer, активный/неизвестный Fail2ban, policy-rc.d или незавершённый dpkg, операция отказывается. Не используйте `docker system prune`, `docker volume prune`, `ufw reset` или `rm -rf` для «очистки».

После успешного `--apply` скачайте/распакуйте свежий комплект и запустите мастер. Обновлённый комплект также проверяет общий размер `/` и при root меньше6ГиБ может расширить только подтверждённый прямой ext4-раздел до доступного конца (не ровно15ГиБ), если диск уже расширен и инструменты `growpart`/`resize2fs` существуют. Сложная схема/stale GPT отклоняется без мутации.

## Отказы и восстановление

- Состояние дизайна/manifest сохраняется для повторного выполнения. Не удаляйте его вслепую.
- Изменения BBR и Fail2ban записываются в приватные журналы восстановления; rollback учитывает собственные файлы/значения, не удаляет чужие конкурентные изменения.
- При последующей неудаче развёртывания сначала подтверждается остановка созданных контейнеров, затем откатываются host features в обратном порядке и UFW. При неопределённом состоянии Docker ограничения API и каталоги сохраняются.
- Runtime устанавливается после готовности сервисов; ошибка его копирования не должна удалять работающую ноду. При ней установка считается неполной, смотрите ошибку и private state.
- APT/Docker-пакеты, образы, логи и тома сертификатов не удаляются автоматическим откатом.
- SIGKILL/отключение питания/дисковые ошибки нельзя полностью исправить Python-handler. Нужен snapshot и консоль провайдера.
