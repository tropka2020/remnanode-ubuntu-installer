# Remnawave Node Installer — Ubuntu 24.04

Установщик Remnawave Node с Caddy, тремя шаблонами сайта и понятным отображением этапов установки.

- **NORTH** — природа и путешествия.
- **STILL** — интерьер, свет и пространство.
- **RITUAL** — кофе и домашние рецепты.

В каждом сайте — главная, список материалов, информация о проекте и **пять отдельных страниц статей**. Фото, шрифты и анимации находятся в локальном комплекте; внешние CDN при посещении сайта не нужны.

> **Статус:** комплект прошёл 433 автоматических теста: 429 успешно, четыре пропущены из-за ограничений Windows на POSIX/symlink-проверки. Полноценная интеграционная установка этой версии на Ubuntu с Docker, ACME, Fail2ban и nftables не выполнялась. Сначала испытайте на одноразовом сервере со snapshot и доступом к консоли провайдера.

## Быстрый запуск

**Скопируйте весь блок целиком и вставьте в терминал нового сервера Ubuntu 24.04.** Это одна составная команда. Тег и GitHub Release не требуются: ZIP загружается из ветки `main`, проверяется по фиксированному SHA-256 и только затем запускается.

```bash
sudo bash -c '
set -Eeuo pipefail
umask 077

URL="https://raw.githubusercontent.com/tropka2020/remnanode-ubuntu-installer/main/remnanode-ubuntu24-premium-v2-nodisklimit.zip"
SHA="8cb5bfc12f8b8b95e8ea1e618829e8e48d277b98da00a813e652d81040bf8414"
TARGET="/opt/remnanode-local"

[ "$(id -u)" -eq 0 ] || { printf "Требуются права root.\n" >&2; exit 1; }
[ "$(uname -s)" = Linux ] || { printf "Запускайте на Ubuntu-сервере, не на Windows.\n" >&2; exit 1; }
command -v curl >/dev/null || { printf "Сначала установите curl: apt-get update && apt-get install -y curl\n" >&2; exit 1; }
command -v python3 >/dev/null || { printf "Требуется Python 3.\n" >&2; exit 1; }

if [ -e "$TARGET" ] || [ -L "$TARGET" ]; then
    printf "Каталог %s уже существует. Ничего не перезаписано.\n" "$TARGET" >&2
    printf "Для установленной ноды используйте selfsteal; не удаляйте каталоги вслепую.\n" >&2
    exit 1
fi

WORK="$(mktemp -d /opt/.remnanode-download.XXXXXX)"
trap '\''rm -rf -- "$WORK"'\'' EXIT

printf "\n[1/4] Скачивание установщика\n"
curl -fSL --proto "=https" --proto-redir "=https" \
    --connect-timeout 15 --max-time 300 --retry 3 \
    "$URL" -o "$WORK/installer.zip"

printf "\n[2/4] Проверка SHA-256 архива\n"
printf "%s  %s\n" "$SHA" "$WORK/installer.zip" | sha256sum -c -

printf "\n[3/4] Распаковка и проверка файлов\n"
python3 -m zipfile -e "$WORK/installer.zip" "$WORK"
(
    cd "$WORK/remnanode-local"
    sha256sum -c SHA256SUMS
)

if [ -e "$TARGET" ] || [ -L "$TARGET" ]; then
    printf "Каталог назначения появился во время загрузки. Установка остановлена.\n" >&2
    exit 1
fi
mv -T -n -- "$WORK/remnanode-local" "$TARGET"
if [ -e "$WORK/remnanode-local" ]; then
    printf "Каталог назначения занят; ничего не заменено.\n" >&2
    exit 1
fi

printf "\n[4/4] Запуск мастера\n"
cd "$TARGET"
bash install-remnanode.sh
'
```

Если вы вошли как `root`, но на сервере нет `sudo`, замените **только начало** `sudo bash -c` на `bash -c`.

Не вставляйте в терминал одну ссылку на ZIP — это не исполняемая команда.

## Что подготовить

- Новый сервер **Ubuntu 24.04 amd64/arm64**, systemd и Python 3.
- Рабочий SSH и доступ к консоли провайдера. Сделайте snapshot.
- Домен с **A-записью непосредственно на IP сервера**, без CDN/proxy. Для текущего IPv4-профиля мастер требует отсутствие AAAA этого домена.
- IPv4 панели Remnawave и `SECRET_KEY` из окна добавления ноды.
- На стороне провайдера разрешённые TCP/80, TCP/443 и ваш SSH-порт. API/2222 нужен только с адреса панели.

**Свободное место:** рекомендуется запас не менее 2 ГиБ. В этой сборке нехватка места/inode вызывает предупреждение, но **не блокирует установку**. Это не отменяет фактическую потребность APT и Docker в диске: если место закончится, установка может завершиться ошибкой. Автоматического удаления данных нет. Для ОС, Docker, обновлений и логов нужен достаточный запас; маленький раздел на 4 ГиБ может оказаться тесным, даже если виртуальный диск у провайдера больше.

## Какие вопросы задаст мастер

1. Домен сайта.
2. IPv4 панели Remnawave.
3. `SECRET_KEY` — скрытый ввод.
4. Шаблон сайта: **1 / 2 / 3**.
5. Подтверждение сводки: введите `УСТАНОВИТЬ`.
6. После настройки UFW: откройте **новое SSH-подключение**. Только при успешном входе введите `SSH РАБОТАЕТ`.

Автономный режим выбирается автоматически. Название, совместимая палитра, порядок материалов и другие параметры оформления выбираются по случайному seed и сохраняются приватно. Вопросов о названии, URL или токене реестра в обычном мастере нет.

> Оформление и статьи могут повторяться на независимых серверах. Случайная генерация не гарантирует визуальную уникальность, нераспознаваемость VPN или прохождение какого-либо сканера.

## Что устанавливается

| Компонент | Назначение |
|---|---|
| Docker Engine и Compose | Установка недостающего Docker из официального подписанного APT-источника |
| Remnawave Node | `remnawave/node:latest`, YAML Compose, `restart: always`, host networking |
| NET_ADMIN и nofile | Сохранены capability и soft/hard-лимиты 1048576 по выбору владельца |
| Сайт и Caddy | Выбранный шаблон, HTTP-01 сертификат, локальный HTTPS backend |
| Logrotate | Файлы Xray: размер 50M, пять архивов, сжатие, `copytruncate` |
| UFW | Сохранение SSH, публичные 80/443, API/2222 только панели |
| Fail2ban | Новый SSH jail после проверки SSH, фактические порты, journald backend |
| Штатный BBR | Проверка поддержки и точечная настройка TCP congestion control |
| Selfsteal | Меню управления сайтом, сертификатом и шаблонами |

Рабочая чужая конфигурация Fail2ban не перезаписывается; при неподдерживаемом или конфликтующем состоянии выводится причина пропуска. BBR также может быть безопасно пропущен. Галочка означает завершение этапа, а не обязательное включение функции, которую система не поддерживает.

## Ход установки

Мастер показывает список этапов с отметками:

```text
[✓] Проверка сервера
[✓] Настройки
[✓] Дизайн
[→] APT/Docker
[ ] Образы
[ ] Сайт/Caddy
[ ] Нода
[ ] Logrotate
[ ] UFW/SSH
[ ] Fail2ban
[ ] BBR
[ ] Selfsteal
[ ] Итог
```

Долгие операции сопровождаются временем ожидания. При ошибке виден этап и ход отката. Вывод с ключами, токенами и секретными аргументами намеренно не печатается. Это не точный процент загрузки Docker-слоёв.

## После установки: профиль создаётся в панели

**Config Profile вы создаёте и назначаете в панели Remnawave.** Установщик сохраняет пример и памятку, но не применяет профиль в панели автоматически.

Файлы на сервере:

- `/opt/remnanode/config-profile.json` — пример серверного профиля с **приватным ключом**; не публикуйте его.
- `/opt/remnanode/host-settings.json` — параметры Host.
- `/opt/remnanode/PANEL-SETUP.txt` — последовательность действий в панели.

Профиль назначается ноде и нужному Internal Squad; Host связывается с соответствующим inbound. Пользователями управляет панель.

| Порт | Назначение |
|---|---|
| TCP/22 или обнаруженный SSH-порт | Администрирование |
| TCP/80 | Caddy HTTP и получение/продление сертификата |
| TCP/443 | Xray после применения профиля из панели |
| TCP/2222 | API ноды, доступ только с IP панели |
| `127.0.0.1:9443` | Локальный HTTPS backend Caddy; наружу не открывается |

До применения профиля **публичный 443 не объявляется работающим**. Мастер проверяет сертификат и HTTP локально на backend. Внешнюю доступность и авторизацию пользователя проверяйте отдельно.

## Логи Xray

На сервере и в контейнере:

```text
/var/log/remnanode/access.log
/var/log/remnanode/error.log
```

Чтобы файлы создавались, в профиле Xray **в панели** должна быть секция:

```json
"log": {
  "error": "/var/log/remnanode/error.log",
  "access": "/var/log/remnanode/access.log",
  "loglevel": "warning"
}
```

Сама установка logrotate не включает файловые логи Xray. Права системного `/var/log` не меняются ради установки.

## Управление сайтом

```bash
selfsteal
```

Меню позволяет посмотреть состояние Caddy и срок сертификата, включить/выключить/перезапустить сайт, открыть логи и сменить шаблон.

```bash
selfsteal status
selfsteal start
selfsteal stop --confirm
selfsteal restart --confirm
selfsteal renew-check
selfsteal logs --kind visits --lines 100
selfsteal logs --kind errors --lines 100
```

Caddy продлевает сертификаты автоматически. `renew-check` не удаляет сертификаты и не обещает принудительную ACME-выдачу на каждое нажатие.

### Смена шаблона

Пункт **8** в меню либо:

```bash
selfsteal template --template 1 --confirm
selfsteal template --template 2 --confirm
selfsteal template --template 3 --confirm
```

Создаётся закрытая резервная копия, меняются только сайт и его manifest. Caddy кратковременно останавливается для переподключения bind mount. При ошибке предусмотрено восстановление. Node, профиль, ключи и тома сертификатов не заменяются.

Менеджер хранится в `/usr/local/lib/remnanode-manager`; команда — `/usr/local/bin/selfsteal`. Чужая команда `selfsteal` не перезаписывается.

## Производительность

BBR включается только при подтверждённой поддержке и отсутствии конфликтов. Существующие `fq`/`fq_codel` сохраняются. MTU, offload, TCP-буферы, backlog, conntrack и сторонние ядра автоматически не меняются; защита не отключается.

**BBR не снимает ограничения тарифа и не гарантирует гигабит.** Итоговая скорость зависит от CPU, провайдера, маршрута, клиента и протокола. UDP он напрямую не ускоряет. Speedtest/iperf и нагрузочный трафик автоматически не запускаются.

## Если установка остановилась

- Не повторяйте удаление/установку вслепую и не сбрасывайте UFW.
- Сохраните текст ошибки и изучите `/var/backups/remnanode-local`.
- Если скачанный комплект уже есть, повторный запуск без повторной загрузки:

```bash
bash /opt/remnanode-local/install-remnanode.sh
```

Это допустимо только пока нода/сайт не установлены: существующие `/opt/remnanode`, `/opt/caddy` или конфликтующие контейнеры вызывают отказ. Для работающей установки используйте менеджер, не мастер.

- Не запускайте `docker system prune`, `docker volume prune` или массовое удаление каталогов без отдельной проверки.
- При предупреждении о диске проверяйте `df -hT /` и `lsblk`: размер виртуального диска и размер раздела могут отличаться. Не форматируйте раздел ради расширения.

## Версия архива и проверка целостности

В корне ветки `main` должен находиться файл с точным именем:

```text
remnanode-ubuntu24-premium-v2-nodisklimit.zip
```

SHA-256 этой сборки:

```text
8cb5bfc12f8b8b95e8ea1e618829e8e48d277b98da00a813e652d81040bf8414
```

При публикации другой сборки обновите **и имя архива, и SHA в команде запуска**. Не отключайте проверку. Старые команды с другими именами ZIP и хешами не обновляются автоматически.

Не публикуйте SECRET_KEY, приватные ключи, токены, серверные manifest/state или индивидуальные отчёты с доступами. Внутри архива находятся `QUICKSTART-V2.md`, `TEST-REPORT.md`, сведения об источниках изображений и лицензии шрифтов.
